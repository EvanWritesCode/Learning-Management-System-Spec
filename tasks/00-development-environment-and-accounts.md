# Task 00 — Local development environment

## Context and dependencies
This is a greenfield private learning app using React + TypeScript + Vite at the repository root, local Supabase Auth/Postgres/private Storage, Cloudflare Pages, and Capacitor Android. This task creates a repeatable local environment. External accounts and release prerequisites are Task 00b; Android tooling and the early shell are Task 02a. Neither is a completion gate here. Task 01 design can start from the plan before local setup finishes. Work on Windows in C:\dev\codex\Learning_Management_System. Read ../IMPLEMENTATION_PLAN.md first.

## Work

### Agent actions: local tools and project bootstrap
1. Inspect what is already installed. Install only missing local web/database tools from official sources: [Node.js 24 LTS](https://nodejs.org/en/download), Git, and [Docker Desktop for Windows with WSL 2](https://docs.docker.com/desktop/features/wsl/). Enable virtualization/WSL 2 if Docker needs it. Android Studio, JDK/SDK components, emulator setup, and device access belong to Task 02a. Vite requirements are documented [here](https://vite.dev/guide/).
2. Create a root Vite React/TypeScript scaffold **without replacing** Initial_Requirements.txt, IMPLEMENTATION_PLAN.md, or tasks/. Use the repository root for package.json, src/, index.html, public/, vite.config.ts, and the Capacitor project later. Pin resolved package versions in package-lock.json; use npm as the single package manager.
3. Install planned runtime libraries: react, react-dom, react-router-dom, @supabase/supabase-js, zod, react-hook-form, @hookform/resolvers, react-markdown, remark-gfm, remark-math, rehype-katex, rehype-sanitize, katex, pdfjs-dist, idb, lucide-react, clsx, @capacitor/core, @capacitor/android, @capacitor/inappbrowser, @capacitor/filesystem, @capacitor/file-transfer, and @capacitor/network. Install development tools: TypeScript, Vite, @vitejs/plugin-react, @types/react, @types/react-dom, eslint, typescript-eslint, prettier, vitest, @testing-library/react, @testing-library/user-event, @testing-library/jest-dom, jsdom, @playwright/test, @capacitor/cli, and supabase CLI. Add scripts for dev, build, typecheck, lint, unit test, and browser test. If package names or peer requirements have changed, use current official-compatible releases and record the exact installed versions in the lockfile.
4. Create .gitignore before handling credentials: ignore node_modules/, dist/, coverage/, .env.local, .env.*.local, Supabase temporary files, and Android build outputs. Commit a safe .env.example with VITE_SUPABASE_URL and VITE_SUPABASE_PUBLISHABLE_KEY placeholders. Do not put secrets in any VITE_ variable. Keep local development values in ignored .env.local; hosted configuration is handled separately in Task 00b.
5. Initialize local Supabase with npx supabase init and npx supabase start. Start Docker Desktop first. The local stack is development-only; never expose it publicly. Record the local API URL, publishable key, and Studio URL in ignored local configuration. Create migrations only in later tasks. The [Supabase CLI guide](https://supabase.com/docs/guides/local-development/cli/getting-started) requires a Docker-compatible runtime.
6. Initialize local Git only if .git is absent, select main as the default branch, and make an initial commit after verifying no credentials are tracked. Remote creation, authorization, and push are tracked separately in Task 00b and do not block local development.
7. Prepare local Supabase confirmation and password-recovery email templates that include the template's Token value as a code, and document the matching hosted Dashboard template changes for Task 27. This lets users enter codes within either the website or Android app instead of requiring mobile deep links. [Supabase email templates](https://supabase.com/docs/guides/auth/auth-email-templates).

## Verification
Run node --version, npm --version, git --version, docker info, npx supabase --version, npx supabase start, npm run build, and npm run typecheck. Open the Vite placeholder in a browser. Confirm ignored .env.local targets local Supabase and no passwords or generated credentials are tracked.

## Done when
The local app builds, the local Supabase stack starts, Git is initialized safely, and local setup is reproducible without hosted accounts, SMTP, remote Git authorization, or Android device access. Track those prerequisites in Tasks 00b and 02a rather than blocking this task.
