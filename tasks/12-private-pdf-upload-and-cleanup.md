# Task 12 — Private PDF upload and file-backed deletion

## Context and dependencies
Tasks 03, 04, 07, 09, and 10 provide durable file-operation records, private Storage policy, chapter editing, import placeholders, and material CRUD. Each uploaded PDF is at most 50 MB and belongs only to the course owner. Database and Storage changes cannot be committed in one transaction, so recovery must survive client termination.

## Work
Add PDF selection, validation by size, declared MIME and file signature, upload progress, cancellation/error feedback, and retry. Resolve PDF placeholders created by Task 09. Serve PDFs through authenticated download or short-lived signed URLs, never a public bucket URL.

Persist an owner-scoped file_operations job before any Storage side effect. Use a unique path for every uploaded version. For upload/replacement, keep the old PDF referenced and readable until the new upload is verified and its metadata link is committed in one database transaction. Commit the job's state with the link change, then remove the old object through a retryable cleanup step. If attachment fails or is canceled, record the new object for cleanup; retain the old link. After a lost response, reconcile persisted job state and current references before retrying or deleting anything. Never remove an object still referenced by an active material.

For material/chapter/course deletion, first record all object paths and mark the target pending deletion in one transaction. Exclude pending-deletion content from normal study, editing, and new downloads, and show a deletion-pending/retry state. Reject competing writes to the target or its descendants. Remove objects through the authenticated Storage API, recording progress idempotently; an already-absent object counts as removed. Only then finalize database deletion and its permitted cascades. A database failure after object removal leaves a durable pending target to finish, not a published broken PDF. If Storage removal fails, retain pending rows and the job for retry. Explain that deletion is pending, not completed or safely undoable once file removal starts.

Resume unfinished jobs after startup and authenticated reconnection for the same owner, including jobs whose target no longer exists. Provide retry/error UI; cleanup may remain pending until that owner returns online, since no background service is included. Use persisted operation state and concurrency control to avoid racing an active upload/commit against cleanup. Keep job authorization until cleanup finishes. Restrict direct database/Storage mutations so they cannot bypass the lifecycle. When Task 14 lands, published material deletion initiation and replacement commit must pass its readiness checks and increment revisions once; reject deletion of the last published material before deleting any bytes. Whole-chapter/course deletion follows its own lifecycle.

## Verification
Upload and view metadata for small and near-limit PDFs; reject files over 50 MB and non-PDF bytes. Inject failure or terminate the app after job creation, upload, metadata commit, each Storage removal, and before final row deletion; restart and verify safe recovery without leaked untracked objects, deletion of an active replacement, or published broken references. Test a lost successful response, repeated retries, concurrent replacement/deletion, cancellation, failed orphan cleanup, and different-user login. Confirm the original PDF remains readable when replacement attachment fails. Test another user cannot fetch or delete objects or forge cleanup jobs. Delete a PDF material and a file-backed course, verify objects and intended attempt cascades are gone, and confirm pending targets stay hidden until finalization. With Task 14, verify last-material deletion is rejected before file removal and revisions advance only once.

## Done when
PDF files are private, size-limited, and correctly linked. Replacement preserves the active file until commit, and every interrupted upload/deletion has a durable, owner-scoped recovery path with an accurate pending or completed state.
