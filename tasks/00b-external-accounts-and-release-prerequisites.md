# Task 00b — External accounts and release prerequisites

## Context and dependencies
This task tracks hosted accounts, repository authorization, and the production email audience independently of local development. Start these user actions early, but they do not gate Tasks 01–26. Local Git setup from Task 00 is needed only for connecting/pushing the repository. All items here must be complete before Task 27 deploys. Android tooling and device access belong to Task 02a. Read ../IMPLEMENTATION_PLAN.md first.

## Work

### User actions: accounts and decisions
1. Sign in to or create a [GitHub account](https://github.com/signup). At [New repository](https://github.com/new), create a **private, empty** repository named Learning_Management_System. Do not add a README, license, or .gitignore on GitHub because local files already exist. Give the coding agent the repository URL, never a password. Local Git is initialized independently in Task 00; the agent can connect and push after the remote exists. If company policy forbids GitHub, stop the Cloudflare Git-connection portion and record the approved Git provider; Cloudflare also supports GitLab.
2. Sign in to or create a [Supabase account](https://supabase.com/dashboard). Create one organization on the **Free** plan and one project named Learning Management System. Choose the region nearest the intended learners, set a strong database password, and store that password in a password manager. In the project Connect dialog or Settings > API Keys, copy the project URL and **publishable** key into ignored .env.production.local when the agent creates it; keep .env.local pointed at the local development stack. Do not share or commit the database password, secret/service-role key, or SMTP password. Supabase's [React guide](https://supabase.com/docs/guides/getting-started/tutorials/with-react) shows the URL and publishable-key locations.
3. Sign in to or create a [Cloudflare account](https://dash.cloudflare.com/sign-up) on the Free plan. Do not create a Pages project until Task 27, after the app builds. At that point the user must authorize Cloudflare to access only this private GitHub repository. [Git integration guide](https://developers.cloudflare.com/pages/get-started/git-integration/).
4. Decide who can receive authentication email. For an **owner-only development pilot**, Supabase's default sender can email project-team addresses, with a low rate limit. For registration and password reset by anyone else, set up custom SMTP before Task 27: create a [Brevo Free account](https://www.brevo.com/), obtain or use a domain you control, authenticate that domain in Brevo using the DNS records it supplies, create and verify a sender address, activate transactional email if Brevo requests it, and create an SMTP key under Settings > SMTP & API. In Supabase Dashboard > Authentication > SMTP Settings, enter sender name/address, host smtp-relay.brevo.com, port 587 (or Brevo's current recommended port), SMTP login, and SMTP **key** rather than an API key. Keep the key only in the providers' settings/password manager. Send confirmation and password-reset test mail to an address outside the Supabase project team. Brevo's free tier currently allows 300 sends/day. If no domain or SMTP account is provided, the release must be labeled owner-only; do not claim open registration works. [Supabase SMTP limits](https://supabase.com/docs/guides/auth/auth-smtp), [Brevo SMTP setup](https://help.brevo.com/hc/en-us/articles/7924908994450-Send-transactional-emails-using-Brevo-SMTP), [Brevo free limits](https://help.brevo.com/hc/en-us/articles/208580669-FAQs-What-are-the-limits-of-the-Free-plan).

### Agent actions
Create an ignored .env.production.local only when hosted settings are needed; retain local Supabase values in .env.local for development and tests. Connect the local Git repository to the user-supplied private remote and push after confirming no credentials are tracked. Record service URLs, Git authorization status, and the selected email audience in a setup checklist, never passwords. Record Cloudflare authorization as pending until Task 27; it is a deployment gate, not a prerequisite for local feature work.

## Verification
Confirm the private remote is reachable and the user can sign in to the hosted services. Verify an outside recipient receives confirmation and recovery test mail if multi-user registration is selected. If SMTP is absent, explicitly select and document the owner/team-only pilot. Check production environment files are ignored and local tests still target local Supabase.

## Done when
The private remote and hosted projects exist, the email audience and its prerequisites are verified, and remaining Cloudflare authorization is explicitly tracked for completion in Task 27. Missing account setup blocks deployment only; do not mark this task complete while its required items are missing.
